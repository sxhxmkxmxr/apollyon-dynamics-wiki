Edge Compute & Custom Inference Engine

At 100 to 270 metres per second, latency translates directly into flight distance committed on stale sensor data. This subsystem provides sub-millisecond execution through hardware-software co-design: isolated CPU cores, custom fused inference kernels, zero-copy direct memory access, and an embedded runtime built for tight power envelopes.

01 · Physical framing

Translating milliseconds into metres of unguided flight

In high-speed autonomous systems, computation latency acts as physical position uncertainty. Generic operating systems and frameworks waste milliseconds on user-to-kernel context switches, dynamic memory allocations, and thread scheduling jitter.

02 · The limit of generic runtimes

Why off-the-shelf deep learning frameworks fail in flight

Standard inference runtimes—including TensorRT, ONNX Runtime, and PyTorch Mobile—are designed for enterprise servers, cloud clusters, and mobile phones. They maximize batch throughput and model operator coverage rather than hard real-time determinism. Inside a high-subsonic weapon, dynamic runtime behaviors cause unacceptable latency spikes:

03 · Architectural mechanism

The proprietary Apollyon execution core

Apollyon deploys an in-house inference runtime designed alongside the onboard silicon. Three design choices ensure deterministic sub-millisecond execution:

Innovation 01

Hand-tuned fused acceleration kernels

Every guidance and perception model compiles into bespoke fused kernels. Operations execute in unified passes without dynamic memory allocations. Intermediate activations stay inside high-speed registers and on-chip caches, eliminating external memory bus bottlenecks.

On-chip intermediatesFused execution
Innovation 02

Deterministic core isolation

Physical CPU cores are partitioned into isolated execution domains. High-rate guidance, sensor fusion, and direct-actuator neural policies execute on dedicated real-time cores running a deterministic microkernel schedule with hardware timer interrupts. Non-critical telemetry and diagnostics run asynchronously on separate cores, eliminating control latency spikes.

Isolated coresDeterministic timing
Innovation 03

Zero-copy direct memory access

Sensors—including global-shutter optical imagers, tactical IMUs, and altimeters—stream telemetry and frames directly into pinned unified memory via Direct Memory Access (DMA). This bypasses intermediate operating system buffer copies and eliminates bus contention.

Sensor direct to GPUZero-copy bus
Thermal and power efficiency at the edge

Expendable strike platforms and interceptors operate inside sealed composite airframes without active liquid cooling. By removing redundant memory copies and optimizing instruction scheduling, the engine draws materially less compute power than generic frameworks. That headroom keeps silicon junction temperatures within rated limits during sustained high-speed sorties.

04 · Engineering discipline

Design against the worst case, not the average

In aerospace flight control, average latency is deceptive. An inference pipeline that averages 2 milliseconds but spikes to 18 milliseconds once every five hundred cycles cannot be trusted in high-G evasive maneuvers or terminal guidance corrections, when compute loads peak.

Every kernel, DMA pipeline, and memory transaction in the compute core is benchmarked against its worst-case execution time (WCET). Flight-test telemetry logs bus latencies at microsecond resolution, and timing budgets are re-derived from measured worst cases rather than nominal averages.
