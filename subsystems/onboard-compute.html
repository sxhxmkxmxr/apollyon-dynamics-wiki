Edge Compute & Custom Inference Engine

At 100 to 270 metres per second, latency translates directly into flight distance committed on stale sensor data. This subsystem provides sub-millisecond execution through hardware-software co-design: isolated CPU cores, custom fused CUDA kernels, zero-copy direct memory access, and an embedded runtime optimized for tight power envelopes.

01 · Physical framing

Translating milliseconds into metres of unguided flight

In high-speed autonomous systems, computation latency acts as physical position uncertainty. Generic operating systems and frameworks waste milliseconds on user-to-kernel context switches, dynamic memory allocations, and thread scheduling jitter.

02 · The limit of generic runtimes

Why off-the-shelf deep learning frameworks fail in flight

Standard inference runtimes—including TensorRT, ONNX Runtime, and PyTorch Mobile—are designed for enterprise servers, cloud clusters, and mobile phones. They maximize batch throughput and model operator coverage rather than hard real-time determinism. Inside a high-subsonic weapon, dynamic runtime behaviors cause unacceptable latency spikes:

03 · Architectural mechanism

The proprietary Apollyon execution core

Apollyon deploys an in-house inference runtime designed alongside the onboard silicon. Three design choices ensure deterministic sub-millisecond execution:

Innovation 01

Hand-tuned fused CUDA kernels

Every guidance and perception model compiles into bespoke CUDA and SIMD kernels. Operations such as LayerNorm, SiLU activation, matrix-vector multiplication, and feature unpacking execute in single kernel launches. Intermediate activations stay inside high-speed GPU registers and shared memory, avoiding high-latency VRAM round trips.

Zero intermediate VRAMFused execution
Innovation 02

Strict real-time core isolation

The system partitions physical CPU cores. Flight-critical guidance and direct-actuator neural loops run on dedicated cores configured with Linux PREEMPT_RT. Non-critical tasks such as telemetry compression run on separate cores, preventing control loop preemption.

Isolated coresNo preemption
Innovation 03

Zero-copy direct-to-GPU DMA

Sensors—including global-shutter CMOS cameras, tactical IMUs, and radar altimeters—stream frames directly into pinned unified GPU memory via PCIe Direct Memory Access. This bypasses the standard triple-copy overhead across Linux kernel buffers.

Sensor direct to GPUZero-copy bus
Thermal and power efficiency at the edge

Expendable strike platforms and interceptors operate inside sealed composite airframes without active liquid cooling. By removing redundant memory copies and optimizing instruction scheduling, the engine lowers compute power draw by over 40% compared to generic frameworks. This preserves silicon junction temperatures within rated limits during sustained high-speed sorties.

04 · Engineering discipline

Design against the worst case, not the average

In aerospace flight control, average latency is deceptive. An inference pipeline that averages 2 milliseconds but spikes to 18 milliseconds once every five hundred cycles will fail during high-G evasive maneuvers or terminal guidance corrections when compute loads peak.

Every kernel, DMA pipeline, and memory transaction in the compute core is benchmarked against its worst-case execution time (WCET). Flight-test telemetry logs bus latencies at microsecond resolution, and any detected timing overrun triggers kernel-level re-profiling.
